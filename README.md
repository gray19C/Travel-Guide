# 旅游攻略 Agent

一个基于 [opencode](https://opencode.ai) 的旅游攻略生成 agent。把「国庆想去云南，7天，两个人」这样一句话，变成一份带来源核实、预算明细和行前清单的可执行行程文档。

完全跑在 opencode 免费模型上，不需要任何付费 API Key。

---

## 功能

- **需求对齐** — 一次问全出发地、日期、天数、同行人、预算、偏好，而不是挤牙膏式追问
- **联网核实** — 价格、营业时间、闭馆日、交通班次、预约要求等易过期信息实时查证，并在正文标注来源链接与查询日期；查不到就写「未核实」，不编造数字
- **结构化产出** — 严格遵循固定模板（行程概览表 → 逐日行程 → 预算明细 → 行前准备清单）
- **自动落盘** — 写入 `guides/<目的地>-<天数>天-<出发日期>.md`，同名文件冲突时先问用户
- **双语景点名** — 每个景点同时给出当地语言原名，方便问路和订票

## 目录结构

```

├── AGENTS.md                          # 项目级规范：攻略模板、命名规则、事实核实要求
├── .opencode/
│   ├── agent/
│   │   └── travel.md                  # travel agent 定义（提示词 + 权限）
│   ├── command/

│   └── skills/
│       └── travel-guide/

```

## 使用方式

### 在 TUI 交互界面里（推荐）

```bash
cd D:\Projects\旅游agent
opencode
```

然后在对话里用斜杠命令：

```
/trip 国庆想去云南，7天，两个人，人均5000，偏好自然风光和美食
```

或者不敲命令，直接用自然语言提需求，agent 会自动接管并开始反问细节。

### 单次无交互执行

```bash
opencode run --dir "D:\Projects\旅游agent" --agent travel "国庆想去云南，7天，两个人"
```

`opencode run` 每次都会启动新进程并重新读取磁盘上的配置，所以改完配置不需要重启任何东西。

### 退出

`/exit`（别名 `/quit`、`/q`），或快捷键 `ctrl+x` 然后按 `q`。

## 工作流程

agent 被触发后会按顺序走这四步：

| 步骤 | 行为 |
| --- | --- |
| 1. 对齐需求 | 一次性问全缺失信息；用户已说清的不重复问 |
| 2. 核实信息 | 联网查证易过期信息，标注来源链接与查询日期 |
| 3. 生成攻略 | 按 `AGENTS.md` 模板输出，每天分上午/下午/晚上三段 |
| 4. 落文件 | 写入 `guides/`，命名 `<目的地>-<天数>天-<出发日期>.md` |

## 权限模型

`travel.md` 的 `permission` 块刻意收得很紧：

| 规则 | 值 | 意图 |
| --- | --- | --- |
| `edit` | `guides/**` 和 `guides\**` 为 `allow` | 只能自由写 `guides/` 目录，其余路径每次都要审批 |
| `question` | `allow` | 必须允许，否则「先问用户」这一步无法执行 |
| `websearch` / `webfetch` | `allow` | 需求就是需要联网核实信息 |
| `bash` | `ask` | 工具保留在列表里，但每次执行命令都要你手动批准 |
| `task` | `deny` | 不允许再派发子 agent |

## 注意事项

### ⚠️ 绝对不要把 `bash` 设成 `deny`

这是本项目踩过的最坑的一个问题，值得单独说明。

把 `bash: deny` 写进 agent 的权限块，会让所有请求直接失败：

```
Error: Error from provider (Console): OpenCode's free tier can only be used from within OpenCode
```

原因不是认证、不是额度、也不是提示词有问题。免费层的门禁靠请求结构指纹判断请求是否来自真正的 opencode 客户端，而**真实的 opencode 代理请求必然带 bash 工具**。一旦用 `deny` 把 bash 从工具列表里摘掉，请求指纹就不匹配了，于是被当成第三方 harness 拦截。

排查过程中容易被误导的地方：报错信息完全不提权限，认证列表也是空的（`opencode auth list` 显示 0 credentials），而且同一时刻 `build`、`plan`、`title` 这些内置 agent 全部正常——因为只有自定义 agent 才会写 `bash: deny`。

正确做法是 `bash: ask`。工具仍然出现在请求里，门禁放行；但 agent 想执行任何命令都得你手动批准，实际约束效果和 `deny` 一样。

**改完 `travel.md` 的权限块后，务必重新跑一次 `opencode run` 验证。**

### headless 模式下的 `ask` 会挂起

`edit` 的兜底规则是 `ask`。在 TUI 里这会正常弹窗给你点，但在 `opencode run` 这种无交互模式下，agent 触发一次 `guides/` 之外的写操作就会无限等待审批，表现为命令卡住不动（我的诊断过程中有个 agent 就是这样超时的）。

无交互执行时尽量把任务范围限定在 `guides/` 内；确实需要放宽就加 `--auto` 跳过审批。

### 攻略质量靠事实核实，不靠模型记忆

价格、营业时间、开放状态、交通班次、预约要求都属于易过期信息。agent 的提示词和 `AGENTS.md` 都强制要求这类内容必须有来源链接与查询日期，查不到就明确写「未核实」。

**生成完攻略请自己复核一遍关键数字**，尤其是需要提前预约的项目和有闭馆日的景点。这不是客套话，是这类工具最容易出问题的地方。

### `temperature` 已移除

提示词里原本有 `temperature: 0.4`，排查过程中被证实与故障无关，已删除。结构化输出靠提示词约束和模板，不靠采样温度。

### 中文输出乱码

在 PowerShell 里跑 `opencode run` 可能看到中文乱码，这是 Windows 控制台的编码问题，不是 agent 故障。需要正常显示可以先执行 `chcp 65001`。
